## 0. 목표·컨벤션 요약
- **신설 슬롯**: 새벽 **06:30 KST 발화**, 미국 현물장 마감(EDT 05:00 / EST 06:00 KST)을 **한국 개장
  동시호가(08:30~09:00) 이전**에 확정. 자정 예측의 `[진행형]` 지정학 역전을 봉합하고 갭 예측·
  `pending_orders` 트리거를 개장 전에 갱신한다.
- **컨벤션(09시 선례 그대로 따름)**: 09 슬롯이 "발화 09:20·슬롯/파일/헤더는 `09`"인 것과 동일하게,
  06 슬롯은 **발화 06:30·슬롯 식별자/파일명/헤더/커밋은 모두 `06`(=`06:00`)** 로 고정한다.

### 3-1. 신규 `prompts/0630_us_close.md`
`prompts/0000_global.md` 를 뼈대로 하되 **미국장 마감 확정 + 개장 전 갱신**에 특화:

- **리포트**: `reports/YYYY-MM-DD-06.md` 신규 생성, 헤더 `## 🌄 06:00 미국장 마감 확정` +

### 3-2. `prompts/0900_pre_market.md` 역할 재조정 (중복 제거)
09시가 하던 "미국장 마감(05:00) 최종 확인"(§1-1)을 06:30 으로 **1차 이관**한다:
- 09시 §1-0 **선제추론 채점은 09시에 유지**한다. 이유: 자정 예측의 `horizon="09:00"`(개장 갭)은
  **실제 개장가가 나오는 09시에만 채점 가능**하다. 06:30 은 개장 전이므로 채점하지 않는다.
- 06:30 이 만든 **갱신 예측**(마감 확정 반영, 새 `inference_log` 행, `horizon="09:00"`)도 09시가
  함께 채점하도록 §1-0 에 "06시 갱신분 포함" 1줄 추가.
- 09시 §1-1 은 "06시 리포트가 있으면 그 마감 확정을 흡수하고, 없으면(미발화) 기존대로 직접 확인"으로
  **폴백 유지**(06:30 미발화 시 09시가 여전히 마감을 잡음 — 안전망 불변).
- 09시 §0 컨텍스트 적재 목록에 **`reports/YYYY-MM-DD-06.md`(있으면)** 를 자정 파일과 나란히 추가.

### 3-3. "시리즈 진행" 줄 6곳 삽입

## 7. 리스크·주의점
- **중복 채점 금지**: 06:30 은 개장 전이라 `horizon="09:00"` 예측을 **채점하지 않는다**(§3-2). 채점은
  09시 단독. 06:30 이 채점까지 하면 이중 집계로 scorecard 오염.
- **서머타임**: 미 마감 EDT 05:00 / EST 06:00 KST. 06:30 발화면 두 경우 모두 마감 후 → OK. 겨울(EST)엔
  마감 30분 뒤라 정착이 빠듯 → 프롬프트에 "마감가 미확정 시 잠정치·09시 확인" 폴백 1줄.
- **09시 안전망 유지**: 06:30 미발화(트리거 실패) 시 09시가 여전히 마감을 잡도록 §1-1 폴백을 **삭제하지
  말 것**. 06:30 은 "앞당김"이지 "대체"가 아니다.
- **카톡 노이즈**: 슬롯 6개로 알림 +1/일. 06:30 은 취침~기상 경계라 수용 가능하나, 원치 않으면
  `send_kakao` 발송부에서 06 슬롯만 조용히(무음) 처리하는 옵션을 별도 검토.
- **아카이브 카운트**: "25→30"은 문서상 안내일 뿐이나, 일요일 archive 프롬프트가 이 숫자로 원본 범위를
  판단하므로 **반드시 함께 갱신**(누락 시 06 파일이 응축에서 빠질 수 있음).

## 10. 전략·흐름 검증 (3차 — 코드 지점이 아니라 슬롯 간 인계 논리를 트레이스)
**검증한 흐름**: 18시(pending_orders 적재·if-then·예측) → 00시(개장 1h 관측·`[진행형]` 태그·갭 예측)
→ **06시(마감 확정·진행형 판정·갭 갱신·트리거 갱신 — 채점 없음)** → 09시(00+06 예측 채점·06 흡수·체결)
→ 12/15(장중) → 18시(06 포함 5개 종합·score_inferences) → 일 21시(6슬롯×5일=30개 응축).

**확인된 안전 성질**:
- **채점 단일 소유**: 06시는 "채점 금지" 명시, 09시가 00·06 두 슬롯의 horizon=09:00 을 채점, 18시는
  "09시가 이미 채점한 것 건너뜀" — 삼중 장치로 중복 채점 없음. `score_inferences.by_slot` 은 동적 집계.
- **매매 금지 체인**: 06시는 trade_log 를 쓰지 않음 → `check_trade_log_gate`(provenance·timing) 무관,
  pending_orders 는 트리거 값·메모만 갱신(status 불변) → 체결 소유권은 09시 게이트에 그대로.
- **타이밍**: 미 마감 EDT 05:00/EST 06:00 → 06:30 발화(여름 +1.5h/겨울 +0.5h 버퍼, EST 잠정치 폴백
  명시) → 동시호가 08:30 까지 2h 여유. Actions 사전 스냅샷은 불필요(§0-A 가 자체 fetch — 00시와 동일 패턴).
- **주말 경계**: 토·일 미발화. 금요일 미국 마감은 월 06:30 주말 마감 모드가 커버(한국장이 없어 그 사이
  액션 불필요), 자정 슬롯은 기존대로 매일 발화 — 슬롯별 발화 요일 차이가 충돌하지 않음.

**발견·봉합한 흐름 갭 (3차 커밋)**:
1. **06시 프롬프트에 한국 영업일 가드 부재(실질)** — 화~금 공휴일(한글날 등)에 정상 모드로 돌면 열리지
   않는 시장의 갭을 예측·적재할 뻔 → §0-B(check_market_open, 휴장 시 갭 예측·inference 적재·주문 갱신
   생략) 신설. market_calendar 의 "06:00" 분기를 프롬프트가 실제로 구현하게 됨.
2. **자정 프롬프트의 인계 체인이 구(舊) 구조(실질)** — `[진행형]` 확인 주체가 "05:00 이후 09시" 로 4곳
   잔존 + if-then 표 헤더 "09시 행동" + 머리말 각주 "09:00 보강" → "마감 후 06시 확정 → 09시 개장 실측
   최종 확인" 이중 구조로 갱신. 이 슬롯의 존재 이유(진행형 역전 봉합)가 상류 문서에 반영 완료.
3. **pending_orders 소유권 서술(문서)** — README 가 "18시가 작성"만 명시 → "06시가 트리거 값만 갱신
   (체결·status 변경 없음)" 추가. Phase 3 안전 못(장중 신호만·체결은 게이트 후)과 모순 없음 확인.
