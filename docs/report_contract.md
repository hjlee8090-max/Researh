# 리포트 형식 계약 (Report Contract) — 단일 스펙

> 목적: 시간대별 리포트의 파서 의존 요소(고정 문자열·구조)를 **한 곳**에 정의한다.
> 이전에는 이 계약이 4곳(send_kakao.py·build_html.py·audit_pipeline.py·프롬프트의 "파서 고정 문자열" 절)에
> 흩어져 있어 한쪽만 바뀌면 "카톡이 안 오는" 형태로만 사후 발견됐다 (진단 I14·I15, plan Phase 1-4).
> 기계 검사: `scripts/check_report_contract.py` (audit 이 매 실행 당일분을 WARN 으로 흡수).

## 0. 계약 소비자 (이 문서와 동기화해야 하는 코드)

| 소비자 | 사용 요소 | 위치 |

| `scripts/send_kakao.py` | 슬롯 헤더(SLOT_META)·`### 한눈에 보기` 추출 | SLOT_META 상수 근처 주석 참조 |
| `scripts/build_html.py` | `오늘의 한줄평` og:description 추출 | `extract_oneline()` |

최근 3일 리포트에 소급 실행(`--days 3`)해 회귀를 확인한다.

## 1. 슬롯 헤더 (고정 문자열 — 1글자도 바꾸지 않는다)

```
00 → ## 🌙 00:00 글로벌 야간 점검
06 → ## 🌄 06:00 미국장 마감 확정
09 → ## 🌅 09:00 개장 점검
12 → ## 🕛 12:00 장중 점검
15 → ## 🔔 15:00 마감 임박 점검
18 → ## 📊 18:00 종합·확정 리포트
```

- 발화 시각이 밀려도(09:20 발화 등) 헤더의 명목 시각은 위 그대로 유지한다 (README 슬롯 관례).

## 2. 필수 구조 요소 (슬롯 리포트 공통)

1. **시리즈 진행 줄**: `> 시리즈 진행:` 로 시작하는 1줄. **6개 슬롯 전부**(🌙 🌄 🌅 🕛 🔔 📊)를
   `✓ / ⚠️(미실행) / 대기` 상태와 함께 표기한다. 일부 슬롯을 빼고 적으면 미발행이 은폐된다(진단 I14).
2. **`### 한눈에 보기`**: 카톡 요약의 추출 원천. 불릿은 `- **라벨**: 값` 형식 — send_kakao 가
   라벨(예: "오늘의 액션", "KOSPI", "촉매")로 요약 줄을 고른다.
3. **`오늘의 한줄평`**: `오늘의 한줄평: <문장>` 형태 1줄 (build_html 이 og:description 으로 사용).
4. **`### 면책`**: 학습·시뮬레이션 고지.

## 3. 금지 요소 (독자 화면 보호)

- **본문 전체**(고정밀 — check_report_contract 검사): 내부 섹션 참조 `§`, 정책/모델 버전 `vX.Y`,
  트리거 ID `po-YYYYMMDD…`.
- **한눈에 보기 한정**(광폭 — audit GLANCE_BANNED_TOKENS 검사): `live_verify`·`web_verify`·`pre_trade`·
  `resync`·`HTTP 403`·`freshness`·`snapshot_age`·`tier=`·`stale`·`mark-to-market`·`time_stop`·`§`.
- 정책 근거가 필요하면 사람 말로 풀고, 상세는 "내부 규칙 문서 참조" 각주로 처리한다.

## 4. 위험 게이지 (확정 규약 — 2026-07-04 Phase 4-6)

- **1줄 텍스트 게이지** (코드펜스·가로 막대 금지 — 모바일 가로 스크롤 방지, I20):
  `- 종목명: 손절 XX,XXX ─ ● 현재 XX,XXX (진입비 ±X.X%) ─ 목표 XX,XXX │ 손절까지 -Y.Y% · 목표까지 +Z.Z% 🟢`
- 현재가 마커 `●` 는 줄당 **정확히 1개**. 트레일링 활성 종목은 `─ 트레일1차 XX,XXX` 를 목표 앞에 추가.
- 손절까지의 거리는 `-X.X%`(하락 거리) 부호로 표기한다 — `손절가까지 +X%` 금지 (진단 I13 부호 반전 사고).
- 수치 원천: `state/exit_levels.json` (손계산·이월 금지). 게재 슬롯: **전 종목 게이지는 00시(야간 추정)·18시(종가 확정)만**, 06/09/12/15시는 변경 종목만(델타) + "나머지 N종목 — 전 슬롯과 동일" 1줄.

## 5. 빈 섹션 금지

- 헤딩 직후 본문 없이 같은·상위 레벨 헤딩이 이어지면 위반(이중 헤딩 — 07-02-09 사고).
- 섹션 제목을 바꿀 때는 구제목을 지우고 신제목만 남긴다(과도기 이중 표기 금지).

## 6. 검사기 사용법

```bash
python scripts/check_report_contract.py                 # 오늘(KST) 슬롯 리포트
python scripts/check_report_contract.py --days 3        # 최근 3일 소급
python scripts/check_report_contract.py --date 2026-07-02 --strict   # 특정일, 위반 시 exit 1
```

- audit_pipeline 이 매 실행 당일분을 자동 검사한다 (WARN — 빌드 차단 없음).
- 리포트 형식을 바꾸는 모든 변경(Phase 4 포함)은 이 검사기의 통과가 배포 전제다.

## 7. 슬롯 미실행·복구 계약 (각 슬롯 프롬프트 가독성 원칙 7번의 원본)

미실행 슬롯의 사후 처리가 규정에 없어 세션마다 임의 행동(23:59 소급 작성 등)이 발생했고,
휴장 생략과 장애 미실행이 같은 표기로 뭉개져 복기·감사가 오분류됐다 (진단 P1).

1. **부재 표기의 사유 구분**: 뒤 슬롯이 이전 슬롯 부재를 적을 때 — 장애·미발화면 `(N시 미실행)`,
   휴장 규칙에 따른 의도된 생략이면 `(N시 휴장 생략)`. 시리즈 진행 줄도 동일 구분(⚠️ vs 휴장).
2. **소급 작성(백필) 기본 금지**: 예외는 다음 3조건 **동시 충족** 시에만 허용 —
   ①당일 중(자정 전) ②파일 머리에 `※ HH:MM 소급 작성` 라벨 명시 ③시리즈 진행 줄은
   실제 발화 시각 기준으로 표기(소급본이 전 슬롯 ✓ 로 위장하지 않는다). 익일 이후 백필은
   금지 — 누락은 audit 슬롯 매트릭스 WARN 으로 기록을 남기는 것이 맞다(이력 위조 방지).
3. **무음 종료 금지**: 자기 슬롯 리포트는 실패·축약·휴장 모드에서도 **반드시 생성·커밋**한다
   (사유 명기). 리포트 부재는 뒤 슬롯·감사가 장애와 휴장을 구분할 수 없게 만든다.

> 참고: 실행 수치(트레일링 1차선·샹들리에·손절·목표)는 `state/exit_levels.json`
> (`scripts/compute_exit_levels.py` 산출)만 인용한다 — 손계산·직전 리포트 이월 금지 (진단 I8·I10).

## 8. 델타·조건부·용어 원칙 (2026-07-04 Phase 4 — 각 슬롯 프롬프트 가독성 원칙의 원본)

하루 산출량의 40~50%가 슬롯 간 반복 블록이라 진짜 변경점이 묻혔다 (진단 I3~I6, R3·R4).

1. **구조(4-1)**: 슬롯 헤더 바로 아래 `### 한눈에 보기`(오늘의 액션 포함)가 본문 최상단,
   블로그 산문은 그 직후 `### 📝 오늘의 이야기`(### 레벨) — 30초 의사결정 우선, 서사는 2순위.
2. **델타 원칙(4-2)**: 같은 날 앞 슬롯과 동일한 블록 재게재 금지. 위험 게이지 전체는 00·18시만
   (§4), 09/12/15시는 변경 종목만. 뉴스 반영 매매가 표는 09시 전체, 15/18시는 Δ 있는 행만
   (전무하면 "직전 대비 변동 없음" 1줄) — 방법론 각주 생략. 종목 카드의 thesis·'초보자 한 줄'은
   09시만, 이후 슬롯은 변화분만. 표에 실은 정보의 불릿 재나열 금지.
3. **조건부 섹션(4-3)**: 체결 표·경보 상세·야간 추가 이벤트는 발생했을 때만 섹션 생성 —
   0건이면 '한눈에 보기' 1구로 흡수(항상-'없음' 섹션 금지 — 알람 피로 방지).
4. **후보 상세(4-4)**: 신규 진입 가능한 날(빈 슬롯≥1·heat 잔여>0·레짐 허용)만 상위 5 상세,
   불가한 날은 "신규매수 불가(사유) + 상위 3 한 줄씩"으로 축약.
5. **용어(4-5)**: `state/glossary.md` 기등재 용어 재정의 금지(용어명만 사용). 처음 풀이한 용어는
   glossary 에 1줄 등재(용어당 3줄 상한). '새 용어' 항목은 신규 등재분 있을 때만.
   같은 사실·수치의 서술은 리포트당 1회.
6. **은퇴 규칙(4-8)**: 새 섹션·표·게이지를 추가할 때는 대체·통합되는 기존 요소를 같은 변경에서
   제거·명시한다 — 순증 금지(재비대 +75~182% 의 재발 방지).
7. **주간 응축 호환**: 델타 원칙으로 09/12/15시에 게이지·매매가 표가 없는 것은 정상이다 —
   `sunday_archive` §2-1 은 부재 섹션을 "(섹션 없음)"으로 처리하지 말고 18시 확정본에서 추출한다.
